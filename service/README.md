# 밀링 기계 고장 예측 서비스

학습된 분류 모델을 활용해 센서 입력의 고장 확률을 보여주는 **Streamlit 웹 서비스**입니다. 단건 입력, CSV 일괄 예측, 가상 밀링 기계 5대의 모니터링을 지원합니다. 데이터 분석과 학습 과정은 [프로젝트 README](../README.md)를 참고하세요.

## 빠른 실행

프로젝트 루트에서 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r service/requirements.txt
.\.venv\Scripts\python.exe -m streamlit run service/app.py
```

이미 준비된 Python 환경을 사용한다면 다음 명령으로 실행할 수 있습니다.

```bash
python -m pip install -r service/requirements.txt
python -m streamlit run service/app.py
```

터미널에 표시된 Local URL로 접속합니다. 기본 설정에서는 `http://localhost:8501`을 사용합니다.

### 준비할 파일과 의존성

| 항목 | 경로 | 용도 |
| --- | --- | --- |
| 모델 | `train/model/models/*_model.pkl` | 예측에 사용할 모델이 최소 1개 필요 |
| 저장된 평가 지표 | `train/model/eval/data/*_eval.json` | 개요·사이드바 성능 표시 |
| 피처 기준값 | `service/artifacts/feature_stats.json` | 원본 입력을 학습 피처로 변환 |
| 원본 데이터 | `data/ai4i2020.csv` | 원본 데이터 일괄 예측 및 기준값 파일이 없을 때 생성 |
| 학습·테스트 데이터 | `train/data/train_data.csv`, `test_data.csv` | 내장 데이터 일괄 예측 |

기본 의존성은 Streamlit, pandas, NumPy, scikit-learn, Plotly, joblib, XGBoost, LightGBM, CatBoost입니다. **TabPFN은 모델 목록에 등록되어 있지만 `requirements.txt`에 포함되어 있지 않습니다.** 사용하려면 같은 Python 환경에 추가로 설치하고, 저장 모델의 학습 환경과 호환되는 PyTorch·GPU 환경을 준비합니다. 현재 학습 코드는 `device='cuda'`로 설정되어 있습니다.

```powershell
.\.venv\Scripts\python.exe -m pip install tabpfn
```

모델 로딩에 실패하면 해당 모델을 건너뛰고 터미널에 원인을 출력합니다. 설치되어 있다는 이유만으로 모든 PKL의 버전 호환성이 보장되지는 않습니다. 새 모델 학습은 [루트 README의 실행 방법](../README.md#실행-방법)을 참고하세요.

## 화면 구성

| 화면 | 주요 기능 |
| --- | --- |
| 개요 · 모델 성능 | 로딩된 모델의 저장된 Accuracy·Recall·Precision·F1 비교, F1 최고 모델 표시 |
| 실제 데이터 입력 예측 | 센서·제품등급 직접 입력, 고장 확률과 판정, 모델 간 비교, 마모·토크 변화에 따른 확률 곡선 |
| 테스트 데이터 예측 | 내장 CSV 또는 업로드 파일 예측, 정답이 있으면 성능 평가, 결과 CSV 다운로드 |
| 실시간 모니터링 (5대) | 가상 센서 생성, 설비별 확률·경보·센서 추이, 공구 교체 및 경보 로그 다운로드 |

### 모델 선택과 판정 기준

세 예측 화면의 사이드바에서 모델과 판정 임계값을 선택합니다. 모델 탐색 순서는 XGBoost → LightGBM → CatBoost → TabPFN이며, 실제로 로딩된 모델만 표시합니다.

- 기본 판정 임계값: **0.50**; 조절 범위: 0.05~0.95, 간격 0.05
- `고장확률 >= 임계값`이면 고장(1), 그 외에는 정상(0)
- 사이드바 평가 지표는 학습 당시 저장된 값이므로 임계값을 바꿔도 변하지 않음

게이지와 설비 카드의 색상 등급은 아래 고정 구간을 사용합니다. 색상 등급과 이진 고장 판정 임계값은 별도로 적용됩니다.

| 고장 확률 p | 표시 등급 |
| --- | --- |
| 0 ≤ p < 0.30 | 정상 |
| 0.30 ≤ p < 0.60 | 주의 |
| 0.60 ≤ p < 0.80 | 경고 |
| 0.80 ≤ p ≤ 1.00 | 위험 |

### 실제 데이터 입력 예측

제품등급, 주변온도, 공정온도, 회전속도, 토크, 공구마모를 입력합니다. 빠른 입력 프리셋은 정상 가동, 과부하, 공구마모 한계, 열방출 위험의 네 가지입니다.

입력으로부터 학습에 사용한 **30개 입력 피처**를 생성하며, 선택 모델의 예측 외에도 로딩된 전체 모델의 예측 비교를 제공합니다. 동력·온도차·마모×토크 조건에 따른 점검 문구, 공구마모·토크 변화에 따른 예측 곡선, 실제 모델 입력 피처도 확인할 수 있습니다. 점검 문구는 코드에 정의된 규칙이고 모델이 예측한 고장 원인 분류는 아닙니다.

### 테스트 데이터 예측

1. 테스트 데이터, 학습 데이터, 원본 센서 데이터 또는 CSV 업로드를 선택합니다.
2. 모델과 임계값을 설정합니다. 데이터가 100행을 넘으면 사용할 행 수를 조절할 수 있으며, 앞에서부터 선택한 행을 사용합니다.
3. 고장 확률 분포와 결과 표를 확인하고 `prediction_{모델명}.csv`를 다운로드합니다.

정답 라벨이 있으면 Accuracy·Recall·Precision·F1과 혼동 행렬을 표시합니다. 정답에 두 클래스가 모두 있으면 ROC-AUC와 ROC·PR 곡선도 제공합니다. 전체 모델 비교 버튼으로 같은 데이터에 대한 성능을 비교할 수 있습니다.

표에는 확률 순으로 최대 300행을 표시하며, 다운로드 파일에는 **이번 예측에 사용한 모든 행**이 포함됩니다. 원본 열 앞에 `고장확률`, `고장예측`을 추가하며 UTF-8 BOM 인코딩으로 저장합니다. CSV 업로드 화면에서 입력 양식도 내려받을 수 있습니다.

### 실시간 모니터링

MILL-01~MILL-05의 센서 값을 랜덤 워크와 고부하 이벤트로 생성하는 **시뮬레이션**입니다. 실제 설비나 센서 서버와 연결하는 기능은 현재 구현되어 있지 않습니다.

| 조작 항목 | 동작 |
| --- | --- |
| 자동 실행 | 기본 켜짐, 설정 주기마다 센서 생성·예측 |
| 갱신 주기 | 1~10초, 기본 2초 |
| 고부하 발생률 | 0~0.5, 기본 0.08 |
| 부하 배율 | 0.8~1.5, 기본 1.0 |
| 한 틱 진행 | 자동 실행을 끈 상태에서 수동으로 한 단계 진행 |
| 초기화 | 설비 상태와 이력 초기화 |
| 공구 교체 | 선택 설비의 공구마모를 0으로 설정 |

공구마모가 240분 이상이 되면 시뮬레이터가 자동으로 공구를 교체합니다. 마모는 틱 단위로 증가하므로 화면 갱신 시간과 실제 가공 시간이 같은 의미는 아닙니다.

설비별 최근 120개 이력과 최근 200개 경보를 메모리에 보관합니다. 경보 표는 최근 50건을 표시하고, 다운로드는 보관 중인 전체 경보를 `fleet_alerts.csv`로 저장합니다. 상태는 Streamlit 세션에서 관리하며 영구 저장용 데이터베이스는 없습니다.

자동 갱신은 `st.fragment`를 지원하는 Streamlit 환경에서 동작합니다. 해당 기능이 없는 버전에서는 자동 실행을 끄고 수동 진행을 사용하거나 Streamlit을 업데이트합니다.

## CSV 입력 규격

UTF-8 또는 UTF-8 BOM CSV를 사용합니다. 원본 센서 형식과 가공 완료 형식을 지원합니다.

### 원본 센서 형식

다음 여섯 열을 모두 포함합니다. 영어 이름은 한글 이름으로 변환되며, 제품등급은 L/M/H 또는 숫자 1/2/3을 사용합니다.

| 한글 열 | 대응 영어 열 | 단위·값 |
| --- | --- | --- |
| 제품등급 | Type | L/M/H 또는 1/2/3 |
| 주변온도_K | Air temperature [K] | K |
| 공정온도_K | Process temperature [K] | K |
| 회전속도_rpm | Rotational speed [rpm] | rpm |
| 토크_Nm | Torque [Nm] | Nm |
| 공구마모_분 | Tool wear [min] | 분 |

```csv
제품등급,주변온도_K,공정온도_K,회전속도_rpm,토크_Nm,공구마모_분
M,298.1,308.6,1551,42.8,0
L,300.4,310.9,1320,60.1,190
H,299.0,309.3,1430,51.0,215
```

선택적으로 `기계고장` 또는 `Machine failure` 열에 실제 정답 0/1을 넣으면 성능 평가를 수행합니다. 센서에는 결측값 없는 수치를 사용하고 공정온도를 주변온도보다 높게 입력합니다. 온도차 로그 계산은 코드에서 최소 1e-6으로 보정하지만, 이 보정이 잘못된 센서 값의 유효성을 보장하지는 않습니다.

### 가공 완료 형식

[config.py](config.py)의 `FEATURE_COLS`에 정의된 30개 열을 모두 포함합니다. 서비스가 해당 순서로 재배열하고 실수형으로 변환합니다. 예시는 [학습 데이터](../train/data/train_data.csv)와 [테스트 데이터](../train/data/test_data.csv)를 참고하세요.

정답을 포함할 경우 열 이름은 `기계고장`을 사용합니다. 피처가 이미 준비되어 있으면 센서로부터 다시 생성하지 않습니다.

## 내부 처리와 파일 구조

```text
원본 센서 입력 → 컬럼·제품등급 정규화 → 기준값을 사용한 피처 생성
가공 완료 입력 ─────────────────────→ 30개 피처 선택·정렬
                                              ↓
                                   모델 predict_proba
                                              ↓
                            고장 확률 → 임계값 판정 → 화면·CSV
```

```text
service/
├── app.py                  # Streamlit 진입점, 개요, 화면 라우팅
├── config.py               # 경로, 모델명, 피처 순서, 위험 등급
├── requirements.txt        # 기본 서비스 의존성
├── core/
│   ├── features.py         # 입력 정규화, 기준값 계산, 피처 변환
│   ├── models.py           # 모델·평가 로딩, 확률 예측
│   └── simulator.py        # 가상 설비·공구마모·이력 관리
├── views/
│   ├── common.py           # 캐시, 모델 선택, 임계값, 게이지
│   ├── single_input.py     # 단건 입력 및 조건별 예측
│   ├── batch_test.py       # CSV 일괄 예측·평가·다운로드
│   └── realtime.py         # 설비 모니터링 화면
└── artifacts/
    └── feature_stats.json  # MinMax, Z-score, 분위수, 센서 범위
```

모델 로더는 모델 객체만 저장된 파일과 `(모델, 평가 dict)` 튜플 모두를 처리합니다. 평가 지표는 JSON을 우선 사용하며, 없거나 비어 있으면 튜플에 저장된 지표를 사용합니다. 모델과 피처 기준값은 Streamlit 캐시로 재사용합니다.

### 피처 기준값 관리

EDA에서 사용한 MinMax 범위, 평균·표준편차, 95%·97% 분위수를 원본 데이터 전체에서 계산해 `artifacts/feature_stats.json`에 보관합니다. 파일이 없으면 원본 CSV에서 자동 생성합니다. 기준값 파일이 이미 있으면 센서 입력 예측을 위해 원본 CSV를 다시 읽을 필요가 없습니다.

데이터·전처리·모델을 함께 갱신한 뒤 기준값을 재생성하려면 프로젝트 루트에서 실행하고 서비스를 재시작합니다.

```powershell
.\.venv\Scripts\python.exe -c "from service.core.features import get_stats; get_stats(refresh=True)"
```

기준값만 임의로 변경하면 기존 모델의 학습 입력과 서비스 입력이 달라질 수 있습니다. 재학습으로 선택 피처가 바뀌면 `FEATURE_COLS`와 피처 생성 코드도 함께 맞춰야 합니다.

## 실행 시 확인 사항

| 증상 | 확인할 내용 |
| --- | --- |
| 모델이 목록에 없음 | 터미널의 모델 로드 실패 로그, PKL 경로, 해당 라이브러리 설치 및 학습 버전 호환성 |
| TabPFN 로드 실패 | 추가 패키지 설치, 저장 모델과 호환되는 TabPFN·PyTorch·CUDA 환경 |
| 원본 CSV를 찾지 못함 | `data/ai4i2020.csv` 존재 여부; 기준값 최초 생성이나 원본 데이터 선택 시 필요 |
| CSV 형식 오류 | 원본 6개 열 또는 가공 완료 30개 열, 숫자형 센서 값, UTF-8 인코딩 |
| 자동 갱신이 동작하지 않음 | `st.fragment` 지원 여부; 자동 실행을 끄고 수동 진행 가능 |
| 모델·기준값 교체 후 이전 결과 사용 | 서비스를 재시작해 캐시를 새로 로딩 |

개요·사이드바의 수치는 학습 시 저장한 내부 평가 결과이고, 일괄 예측 화면의 수치는 선택한 데이터·행 수·임계값으로 계산한 결과입니다. 학습 데이터 평가에는 학습에 사용된 표본이 포함되며, 저장된 테스트 CSV도 SMOTENC 증강 후 분할한 데이터입니다. 평가 분할과 해석상의 한계는 [프로젝트 README](../README.md#데이터-분할-과정)에 설명되어 있습니다.
